## 第 0 章 摘要与导览

### 0.1 一句话定位

**Scientist Lab** 是在**人类冻结科研协议**与**确定性治理边界**内，使 AI 基于真实 GPU 实验形成「假设—计划—物化契约—门禁—执行—读数—审阅—记忆—下一轮」闭环的可控自主科研系统；Git、实验账本、Evidence-linked Memory 与 **Runtime Trajectory 旁路导出**共同支撑可审计学习与未来参数级训练数据供给。

**不是**：多 Agent 堆叠、无人监管发论文机、把「接了 LLM API」等同于 AI Scientist、更好的检测器本身。

### 0.2 三条核心主张

1. **人冻宪法，AI 跑闭环**：Human Gate 只能批准 `approval_required` 动作，不能绕过 `forbidden`/`frozen`；改切片/指标/evaluator 须 Protocol Amendment（`protocol_version++`）。
2. **KEEP ≠ Claim**：DecisionRubric 的 KEEP/DISCARD 决定下一动作；ClaimGate 独立判定科学声称强度（C0–C4）。性能方向性上涨 ≠ G2 成功声明。
3. **单事实流，双轨学习**：Canonical Research Events 一次写入；MVP 经 Memory 证明行为层非参数适应；Trajectory Export 为未来 SFT/DPO/RL 预留旁路，**不宣称基模已被训强**。

## 第一章 研究背景及研究现状

### 1.1 研究背景

#### 1.1.1 AI for Science：从单次调参到长轮次自主实验迭代

2026 年 RSI（递归自我改进）已从概念进入工程事实：OpenRSI、BigBang、Recursive、Sakana AI Scientist 等系统层工作拥挤入场。但开放科研领域**没有廉价可靠的自动答案**——「实验做得好不好」无法像代码单元测试那样即时判分。行业需求从「接一次 LLM 调参」升级为：**在受控边界内，AI 能否连续多轮提出假设、设计对照实验、吸收负结果并改向**。

#### 1.1.2 低照度 RGB-T 小目标检测的科研痛点

- **场景**：RGB 视觉质量下降时，Thermal 模态提供互补信息；融合策略（early_concat、gated_multiscale 等）成为可检验变量。
- **评价要求**：须在**冻结切片**（`low_light_subset_v1`）上评**小目标 AP**（`APS_lowlight`），而非泛泛全集 mAP。
- **与系统边界的关系**：该任务是 **DEMO 验证案例**（研究问题兼容性证明），**不是** Scientist Lab 的系统能力边界；系统应能迁移到其他冻结协议下的科研任务。

#### 1.1.3 自主 Agent 系统的信任危机

- Claim 与 Evidence 混淆（文献摘要 ≠ 本机实验证据）
- 不可审计的「黑箱决策」（无法回答「第 N+1 轮为何出现」）
- 不可复现的指标声称（probe 冒充 formal、mAP 冒充 APS）
- 约 57% 自动生成论文含虚假数据（AI Scientist v2 外部批评）

### 1.2 研究现状

#### 1.2.1 自动化 ML 与 LLM 科研助手

AutoML、文献 RAG、代码生成式实验平台已成熟；但多数系统把「生成代码/跑实验」与「科学声称/对照语义」混在同一层，缺乏独立的 ClaimGate 与 frozen fingerprint 机制。

#### 1.2.2 RGB-T 融合策略与 D-FINE 检测 baseline

- 历史主线：A2 → K 系列诊断 → A4 → P01（**重演基准**，非 LLM 发现）
- v2.6 起点：D-FINE + F1 `early_concat` + `low_light_subset_v1`
- A4（early_concat + FDPN）对 Planner **默认隐藏**，禁止包装成 LLM 成果

#### 1.2.3 可控 Agent 架构实践

GateEngine（Protocol / Risk / Fingerprint）、DecisionRubric（KEEP/DISCARD/REPLICATE）、Evidence-linked Memory、Research Trace（轮级 N→N+1 因果审计）等机制已在 Scientist Lab MVP（tag `mvp-freeze-m1-m4-claimgate-c1`）中冻结验证。

#### 1.2.4 现有方案的不足：轨迹记录与训练数据侧缺口（重点）

> 对应 [AI-Scientist-技术报告-总稿.md](../../AI-Scientist-技术报告-总稿.md) §2.4–2.5 与 [设计架构.md](../../设计架构.md) §0.2 的合意表述。

##### 1.2.4.1 基础设施层拼图 vs 空白

| 已有拼图 | 缺什么 |
|----------|--------|
| **ATDP 六元组**（AReaL 2.0 等） | 通用 Agent 轨迹，**无** phase / claim / evidence 等科研语义字段 |
| **OpenDiscoveryTrace**（ICML'26） | **离线**评测数据集，非运行时记录器；无法服务在线 RL |
| **OpenRSI / Recursive / BigBang** | 程序演化或数据合成日志，**非**开放科研全流程行为记录 |
| **Aviary / TraceBrain** | 偏数据组织或通用日志升级，**无**科研对照语义 |

##### 1.2.4.2 系统层方案的轨迹治理弱项

| 系统 | 强项 | 轨迹/训练数据缺口 |
|------|------|-------------------|
| **AI Scientist v2**（Sakana, Nature 2026-03） | 端到端 idea→实验→写作→自评；树搜索 | 反馈 = LLM/VLM 软打分；**无轨迹化 RL 训练**；论文/代码/Claim 混写 |
| **Anaxa** | Project/Run/Artifact/Evidence/Claim Gate；可复现 bundle | ledger 可追溯，但**对照语义**（空转/单变量/假对照）与训练导出非一等公民 |
| **Auto Research 类**（autoresearch / AI-Researcher 等） | 代码/训练自动优化；固定时间预算短循环 | 程序演化日志为主；**非开放科研**；无 claim/evidence 字段；常限 nanoGPT/MLE |
| **DGM / AlphaEvolve** | 脚手架/算子演化 | 只记「改了什么代码、得分多少」；底层权重或领域受限 |

##### 1.2.4.3 训练数据侧三类普遍缺失

1. **对照标签层**：`how_contrast` / `idle` / `confound`——不看检测分数判 Planner 决策质量（见 `LLM_POSTTRAIN_DATA_STRATEGY.md`）。
2. **人话 story 层**：「看见 → 决定 → 发生」三拍；禁止只存 `how_id=F3`（背编号不会做研究）。
3. **血统与重建标记**：历史 run 可 `reconstructed=true`，**不得进高可信 SFT 桶**；人闸事件默认 `training_eligible=false`。

##### 1.2.4.4 Scientist Lab 的填补路径（三条轨迹边界）

```text
① Single Fact, Multiple Views
   Plan/Gate/Run → Canonical Research Events（append-only）
   → Ledger / Research Trace / Runtime Trajectory（投影）

② Recording Must Not Control Research
   轨迹只记录，不参与 Planner/Gate；reward_export 事后派生

③ MVP Learns Through Memory, Future Models Learn Through Trajectories
   M2–M4 = 行为层非参数适应；SFT/DPO/RL = M4+ 旁路接口
```

### 1.3 本项目总体思路概述

- **Architecture Freeze**：总体架构停止修改；HOW 插件 / LiteratureRetriever / Dataset Workspace / LLM HOW 生命周期为 Adapter 与受控工具**派生**（§18–§19），不加第五 Agent。
- **6 层 + 1 条主闭环**：Human Governance → Protocol/Plan/Contract → Manager + 三 Agent + 确定性服务 → Execution → Memory/Events/Trace/Trajectory。
- **v2.6 战役定位**：验证 Live LLM 在人冻协议下能否推动 `APS_lowlight` 相对 R0 方向性进步，并测试策略向第二检测器迁移。

### 1.4 文档结构说明

本大纲八章对应 §0.3 结构图；第 5–6 章分别对应 **V2.3 执行底座**与 **V2.6 认知闭环**两次实验验证；第 7 章专述轨迹导出；第 8 章含完成度表与附录索引。

## 第三章 设计原则与治理模型

### 3.1 Architecture Freeze 原则

1. **人管制度，Manager 管过程**；人控制 ≠ 人每轮干预。
2. **不堆 Agent**：Manager + Planner + Executor + Reviewer（四个角色）。
3. **确定性问题交给系统，模糊科研判断才交给 LLM**。
4. **科研负结果 ≠ 执行异常 ≠ 无效证据**（三字段状态机）。
5. **Executor 只执行已批准的 ExperimentContract**。
6. **核心对象克制**：6 个项目级聚合；Trace/Trajectory/Events 非第七聚合。
7. **Planner 决定 WHAT/WHY，Adapter 只做 HOW 翻译**。
8. **学习必须可审计**：Lesson 绑定 Evidence；Plan 强制 `memory_refs`。

### 3.2 Human Governance 与动作三态

| 语义 | 含义 | Human Gate 能否放行？ |
|------|------|----------------------|
| **AUTO_ALLOWED** | 当前协议下 AI 可自动做 | 不需要人 |
| **HUMAN_APPROVAL_REQUIRED** | 须人批准后本轮可继续 | **可以** |
| **FORBIDDEN**（含 frozen） | 当前宪法禁止 | **不能**；人也不能绕过 |

**frozen 示例（v2.6）：** `dataset_split`、`evaluator`、`metric_definition`、`low_light_subset_v1`

### 3.3 Protocol Amendment

```text
请求修改科研制度（如 max_rounds、主指标）
  → 停止当前实验循环
  → Human 修改 ResearchProtocol
  → protocol_version += 1
  → 重新冻结
  → 旧版本结果不可与新宪法静默混比
```

**已发生 Amendment 实例：**

| 日期 | 变更 | 裁决文件 |
|------|------|----------|
| 2026-08-20 | `max_rounds` 5→6（Human Gate A） | `DECISION_HUMAN_GATE_A.md` |
| 2026-08-26 | `max_rounds` 6→12；`protocol_version` 1→2 | `DECISION_LLM_HOW_LIFECYCLE.md` |

### 3.4 ClaimGate 与 KEEP ≠ Claim

| 层 | 职责 | 是否 LLM |
|----|------|----------|
| **DecisionRubric** | KEEP / DISCARD / REPLICATE / INCONCLUSIVE | 否（确定性） |
| **Reviewer** | 结构化 lessons/strategy 提议 + 语义解释 | 是（Live API） |
| **ClaimGate** | 证据允许声称到 C0–C4 哪级 | **否**（确定性规则服务） |

**不变量（全文贯穿）：**

- **KEEP ≠ Claim**：Rubric KEEP 只表示「值得继续探索/保留 commit」，不自动升级科学声称。
- **LiteratureEvidence ≠ ExperimentEvidence**：文献不能替代本机 GPU 证据进 ClaimGate。
- **probe ≠ formal**；**mAP ≠ APS**；**early_concat ≠ FDPN**。

### 3.5 失败三分流

| 类型 | 状态 | 处理 |
|------|------|------|
| 科研负结果 | COMPLETED + VALID + DISCARD | 进 Evidence-linked Memory；commit 保留 |
| 执行异常 | FAILED | RETRY_EXECUTION 或 HUMAN_REQUIRED |
| 无效证据 | INVALID / INCOMPLETE | 禁止进科研结论 |

```text
                               ↓

└──────────────────────────────┬──────────────────────────────────────┘

└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 核心对象契约

| 对象 | 含义 | 谁写 |
|------|------|------|
| **ResearchProtocol** | 项目生命周期稳定规则（宪法） | Human 冻结 |
| **ExperimentPlan** | 本轮 AI 提案（含 `memory_refs`） | Planner |
| **ExperimentContract** | 获准后的冻结执行契约 | Adapter.materialize + Gate |
| **ReviewDecision** | Rubric 结果 + lessons/strategy | Reviewer + MemoryWriter |
| **Canonical Research Events** | append-only 事实流 | EventAppender |

### 4.3 最新设计：人冻协议 + LLM 扩展权限（2026-08-26）

#### 4.3.1 权限边界总览

| 角色 | 可做什么 | 不可做什么 |
|------|----------|------------|
| **Human** | 冻结/Amendment Protocol；战役级 `--confirm-human-gate` | 用 Gate 绕过 forbidden；每轮改切片 |
| **LLM Planner** | WHAT/WHY；选已物化 HOW；`memory_refs` | 改 Protocol；Plan 夹 Python；发明未注册 HOW |

| **Gate / ClaimGate** | 协议裁决；声称强度 | — |

#### 4.3.2 HOW 生命周期主链

```text
Human 冻结 ResearchProtocol（切片 / APS_lowlight / Gate / ClaimGate / max_rounds=12）
  → 一次「开始自主实验」（Human Gate）

  → Planner 只选可物化 HOW（主目录 ∪ overlay）
  → Adapter.materialize → GateEngine → Frozen Contract
  → 真实 GPU → Rubric → Reviewer → Memory
  → 下一轮（空转同一 HOW+同一 seed 被拦）
  → STOP / NEED_HUMAN / NOVELTY_EXHAUSTED
```

**决议链：**

- `DECISION_OPEN_HOW_PLUGIN.md`：Adapter 侧写插件；Diff 沙箱 + smoke
- `DECISION_LLM_HOW_LIFECYCLE.md`：战役内 LLM 管 add/author/accept；`llm_how_lifecycle=true`

#### 4.3.3 12 轮长循环战役

| 参数 | 值 | 说明 |
|------|-----|------|
| `protocol_version` | **2** | Amendment 后 |
| `stop_rules.max_rounds` | **12** | 6→12（2026-08-26） |

| ClaimGate | **仍 C0** | 成功也不自动升 G2 |

> **口径**：12 轮是**能力边界验证**协议上限，不是「已跑完 12 轮」或「G2 成立」的声称。GPU 验证待用户在 `/loop` 点一次开始。

### 4.4 确定性服务层

## 第七章 轨迹记录与训练数据导出

> **定位**：Trajectory 是同一事实流的**步级导出投影**（sidecar），不是系统主角，**不参与** Planner/Gate 决策。  
> **权威文档**：`docs/research/v26/LLM_POSTTRAIN_DATA_STRATEGY.md` · `schemas/trajectory_step.schema.json`

### 7.1 设计原则（复述 §1.2.4 三条边界）

1. **Single Fact, Multiple Views** — `research_events.jsonl` 为唯一事实源
2. **Recording Must Not Control** — 轨迹不改 Rubric/KEEP/ClaimGate
3. **MVP 经 Memory，未来经 Trajectory** — 行为层学习已证；参数学习为旁路

### 7.2 数据流：Canonical Events → ATDP → SFT Sidecar

```text
Plan / Contract / Run / Result / Review
  + research_events.jsonl（Canonical，append-only）
        ↓ TrajectoryExporter（只读）
  export/traces/<run_id>.jsonl          # ATDP 六元组，每轮 4 步
        ↓ story + label_contrast
  export/sft|dpo|rl/*.jsonl             # 训练 sidecar
```

### 7.3 ATDP 六元组与每轮四步

**六元组：** ⟨o, h, a, y, r, m⟩

| step_index | step_kind | 训练用途 |
|------------|-----------|----------|
| 1 | `plan_proposal` | SFT 输入 = 观察 o（**不含**检测分数） |
| 2 | `gate_decision` | 人闸样本通常 `training_eligible=false` |
| 3 | `execution` | y 含 metrics；**不进对错标签** |
| 4 | `review_decision` | KEEP ≠ Claim；结构化 decision_summary |

- **r_t 恒为 null**（live export）；奖励仅在 `reward_export` 副本（`contrast_v1` 规则分）
- **h_t** = `decision_summary` 结构化短句，**非隐式 CoT**

### 7.4 SFT Sidecar 三层结构

```json
{
  "story": {
    "saw": "上一轮已用 F1 拼接融合 + seed 42 跑过；只能换融合做法",
    "decided": "下一轮改 F3 门控双路融合，种子仍 42",
    "happened": "合同被执行；APS 写入科学笔记，不作决策标签"
  },
  "machine": {
    "anchor": "outputs/v26_r0",
    "plan": "experiment_plan_rgbt_dfine_v26_r1.json",
    "executed": "outputs/v26_r1"
  },
  "contrast_label": "how_contrast"
}
```

**对照标签枚举：**

| 标签 | 含义 | 训练用途 |
|------|------|----------|
| `how_contrast` | 公平单变量对照（如 F1→F3，seed 不变） | SFT 正样本 |
| `idle` | 空转（同 HOW+同 seed） | DPO 拒绝样本 |
| `confound` | 多变量混淆 | 拒绝 / 降权 |
| `replicate` | 同 HOW 换 seed | 稳定性，非方法对照 |

### 7.5 训练策略摘要

| 算法 | 学什么 | 奖励/标签来源 |
|------|--------|---------------|
| **SFT** | 看见 → 决定（中文 + 合同） | 仅 `how_contrast` 真对照 |
| **DPO** | 同局面好/坏决定对 | F3/42 vs F1/42 空转 |
| **RL** | 合法 HOW、单变量、不空转 | **规则分**；**不用 APS 当 reward** |

**规模建议：** 先 200 条跑通 pipeline；正式 500–2000 条；holdout 考题 `LLM_HOLDOUT_EXAM_CONTRAST_V1` **永不进训练目录**。

### 7.6 CLI 与实现

```bash
scientist-lab export-trajectory \
  --run-dir outputs/v26_r1 \
  --parent-dir outputs/v26_r0
```

| 组件 | 路径 |
|------|------|
| 导出器 | `src/scientist_lab/llm/trajectory_export.py`（`EXPORTER_VERSION=atdp6_v1`） |
| Schema | `schemas/trajectory_step.schema.json` |
| 测试 | `tests/llm/test_trajectory_export.py` |

**保证：** 只读导出；不改账本；不跑 GPU；不伪造指标。

```text
主闭环学习（已证 MVP）          旁路学习（接口就绪，飞轮未跑）
```
