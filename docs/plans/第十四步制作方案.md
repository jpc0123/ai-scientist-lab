> **本文档为 v1.4 权威实现方案。**

## 0. 目标与最终定义

接入统一的 `OpenAICompatibleProvider`（兼容官方 OpenAI、中转站、NewAPI、本地服务）。

### 0.1 必须保证

- 默认仍然是 mock
- 离线测试完全不访问网络
- CI 默认不需要 API Key
- 真实调用必须**三重显式启用**（配置 + `LLM_ALLOW_NETWORK` + CLI `--provider real --allow-network`）
- 有预算、超时、重试与并发保护
- 可生成 Replay，但不得记录密钥和敏感请求头
- 真实输出仍经 CandidateVerifier / Protocol / 预算 / 人工审批，不能自动执行实验

### 0.2 不做（延期）

流式输出、Function Calling、多模态、多 Provider 自动路由、模型自动降级、语义缓存、并行 Planner/Critic、多租户密钥管理、Web 控制台。

多 Provider 路由 → v1.5；工具调用与受限源码补丁 → v1.6。

### 0.3 v1.4 最终交付定义

> Scientist Lab 在保持 Mock 默认、离线测试零网络和人工审批边界不变的前提下，能够显式接入一个 OpenAI-compatible 云模型，安全执行结构化 Planner/Critic 调用，并对请求、响应、预算、错误、Replay 和质量结果进行可追溯审计。

v1.4 **不代表**：AI 完全自主科研、无限调用、LLM 自由改实验/代码。

## 4. 总体架构

```text
PlanningContext / CriticContext
        │
        ▼
Planner / Critic
        │
        ▼
LLMProvider
├── FakeProvider
├── ReplayProvider
├── NullLLMClient          # 可选：显式禁用网络的占位
└── OpenAICompatibleProvider
        │
        ▼

```

核心原则：

```text

业务层不知道 HTTP Header
业务层不知道具体中转站
业务层只依赖 LLMProvider 接口
```

Provider 负责：

```text
读取安全配置
构造请求
执行超时和重试
解析供应方响应
标准化 token usage
分类异常
生成脱敏审计记录
按策略生成 Replay
```

## 6. Provider 统一接口

沿用 v1.3 的 `LLMProvider`，不因接入真实模型而改变 Planner/Critic 调用方式。

目标形态（可与现有 `complete` 并存，由适配器桥接）：

```python
class LLMProvider(Protocol):
    @property
    def provider_name(self) -> str: ...

    def generate_structured(
        self,
        *,
        request: "LLMRequest",
        response_model: type[T],
    ) -> "LLMResult[T]": ...
```

统一请求 / 结果字段（目标模型；实现时映射到现有 `LLMRequest` / `LLMResponse` / `TokenUsage`）：

```text
LLMRequest: request_id, task_type/purpose, messages, response_schema,
            temperature, max_output_tokens, metadata

LLMResult: request_id, provider, model, output, raw_text_sha256,
           usage, latency_ms, provider_request_id, replay_id
```

业务层只能消费：`output` / `usage` / `latency_ms` / `provider_request_id`。  
不得消费供应商原始 Header 或认证信息。

审计保存脱敏的 `provider_request_id`，**不**保存认证请求头。

## 7. OpenAICompatibleConfig

在 v1.4.1 `LLMConfig` 基础上扩展完整模型：

```python
class OpenAICompatibleConfig(BaseModel):
    provider: Literal["openai-compatible"] = "openai-compatible"
    base_url: str
    api_key: SecretStr
    model: str
    api_mode: Literal["chat_completions", "responses"] = "chat_completions"
    timeout_seconds: float = Field(default=60, gt=0, le=600)
    connect_timeout_seconds: float = Field(default=10, gt=0, le=120)
    max_retries: int = Field(default=1, ge=0, le=5)
    retry_base_seconds: float = Field(default=1.0, ge=0.1, le=30)
    retry_max_seconds: float = Field(default=20.0, ge=1, le=120)
    max_concurrency: int = Field(default=1, ge=1, le=16)
    default_max_output_tokens: int = Field(default=2048, ge=1, le=65536)
    allow_network: bool = False
    verify_tls: bool = True
    organization: str | None = None
    project: str | None = None
    extra_headers: dict[str, str] = Field(default_factory=dict)
```

### 7.1 API 模式策略

```text
默认：chat_completions（兼容面更广）
可选：responses（显式配置）
```

**禁止**运行时自动猜测或静默切换。  
`api_mode=responses` 但服务不支持 → `UnsupportedAPIModeError`。

### 7.2 Base URL 规范化

兼容：`https://api.example.com/v1`、带尾斜杠、`http://127.0.0.1:8000/v1`。

规则：

```text
去除末尾多余 /
不得为空
必须是 http 或 https
默认要求 https
localhost / 127.0.0.1 可使用 http
```

不允许：`file://`、`ftp://`、相对路径、URL 中携带 API Key。

### 7.3 Header 白名单

内部自动构造：`Authorization: Bearer <secret>`、`Content-Type: application/json`。  
可选：`OpenAI-Organization`、`OpenAI-Project`。

`extra_headers` **禁止覆盖**：

```text
Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-API-Key
```

Header 名称与值禁止换行符（防 Header 注入）。

## 8. Provider Factory

```python
def create_llm_provider(config: LLMRuntimeConfig) -> LLMProvider:
    match config.provider:
        case "mock" | "fake":
            return FakeProvider(...)
        case "replay":
            return ReplayProvider(...)
        case "openai-compatible":
            if not config.allow_network:
                raise RealProviderNotEnabledError(...)
            return OpenAICompatibleProvider(...)
        case _:
            raise UnsupportedProviderError(...)
```

必须满足：

```text
默认配置 → Fake/Mock Provider
未显式 allow_network → 真实 Provider 不得实例化
CI → 不读取真实 Key，不建立网络连接
Replay → 不检查 LLM_API_KEY
```

双重门禁环境变量：

```text
LLM_PROVIDER=openai-compatible
LLM_ALLOW_NETWORK=true
```

CLI 还必须显式：`--provider real --allow-network`。

**三重同时满足**才允许真实请求：

```text
1. 配置选择 openai-compatible / real
2. 环境 LLM_ALLOW_NETWORK=true
3. CLI 显式 --provider real --allow-network
```

禁止仅靠环境变量让旧命令突然访问网络。

## 9. v1.4.2：OpenAICompatibleProvider 最小闭环

### 9.1 请求流程

```text
接收 LLMRequest
→ 检查真实调用门禁
→ 检查预算
→ 获取并发许可
→ 构造供应方请求
→ HTTP 调用（Transport）
→ 提取文本和 usage
→ SchemaParser 解析
→ Pydantic 校验
→ 生成 LLMResult / LLMResponse
→ 写脱敏审计
→ 可选写 Replay
```

### 9.2 Chat Completions 映射

标准 `model` / `messages` / `temperature` / `max_tokens`。

结构化输出优先级：

```text
1. 服务支持 JSON Schema → 严格 Schema
2. 仅支持 JSON Object → 请求 JSON Object
3. 不支持 → Prompt 要求纯 JSON + 本地严格校验
```

**不得**因供应方不支持 Schema 而跳过本地校验。

### 9.3 Responses 映射

`api_mode=responses` 时使用独立 `ResponsesRequestBuilder`，不与 Chat Completions 请求体混写。

### 9.4 最小结果解析

兼容：usage / finish_reason 缺失、request ID 仅在 Header、content 为字符串或内容块数组、Markdown JSON 代码块、前后杂讯。

允许：去 ```json、去空白、提取唯一顶层 JSON 对象。

不允许：猜测缺失字段、补造科研结论、改非法枚举、删实验约束后继续。

### 9.5 v1.4.2 完成标准

- [ ] OpenAICompatibleProvider 实现统一接口
- [ ] Chat Completions 最小闭环
- [ ] Responses 模式可显式选择
- [ ] MockTransport 单元测试零网络
- [ ] 输出进入统一 SchemaParser
- [ ] usage 和 request ID 可标准化
- [ ] 审计不包含密钥

### 9.6 v1.4.2 测试清单（§26）

## 10. SchemaParser 与结构修复

```text
raw → normalize → JSON decode → model_validate → success
```

失败后允许 **最多一次** 结构修复请求（同 Provider/模型；单独 usage；计入预算；独立审计；不覆盖原始失败记录）。

第二次仍失败 → `StructuredOutputValidationError`。  
异常最多保留有限脱敏错误，不保存完整敏感 Prompt。

## 12. HTTP 状态分类

| 情况 | 异常 | 自动重试 |
|------|------|----------|
| 400 / Schema 请求错误 | `LLMInvalidRequestError` | 否 |
| 401 | `LLMAuthenticationError` | 否 |
| 403 | `LLMPermissionError` | 否 |
| 404 | `LLMInvalidRequestError` | 否 |
| 408 | `LLMTimeoutError` | 是 |
| 409 | `LLMServerError` | 可选 |
| 429 | `LLMRateLimitError` | 是 |
| 500–599 | `LLMServerError` | 是 |
| DNS / 连接失败 | `LLMConnectionError` | 是 |
| 客户端读取超时 | `LLMTimeoutError` | 是 |
| JSON 非法 | `StructuredOutputValidationError` | 只允许修复一次 |

供应方错误正文：限制长度、脱敏、不原样抛给 CLI。

## 13. RetryPolicy

```python
class RetryPolicy(BaseModel):
    max_retries: int = 1
    base_delay_seconds: float = 1.0
    max_delay_seconds: float = 20.0
    jitter: bool = True
```

退避：`min(max, base * 2^attempt) + jitter`。

限制：默认最多重试 1 次、配置上限 5；认证/权限/配置/Schema 请求错误不重试；每次重试独立审计；有计费可能的响应计入预算。  
可在安全范围内采用供应方建议的 Retry-After。  
重试不覆盖第一次失败记录。

## 14. 超时策略

区分 connect timeout 与 read/total timeout。

默认：连接 10s，总 60s。

建议上限：Planner 60s、Critic 60s、Schema repair 30s。

超时后：记录 timeout → 按 RetryPolicy → 最终失败不生成 Plan/CriticReview。  
不得把超时后的空输出当成合法结果。

## 15. LLM 预算体系

实验预算与 LLM 调用预算**分开**。新增 `budget.py`：

```python
class LLMBudget(BaseModel):
    budget_id: str
    project_id: str
    max_requests: int
    max_input_tokens / max_output_tokens / max_total_tokens / max_cost_usd
    used_* ...
    enabled: bool = True
```

调用前检查额度；调用后更新实际 usage。  
usage 缺失：`usage_unknown=true`，可用本地估算或留空，**不得伪造精确 token**。  
不足 → `LLMBudgetExceededError`，且**不得发送网络请求**。

### 15.1 价格配置

`ModelPricing` 独立配置，不硬编码进 Provider。  
中转站/本地价格未知 → `estimated_cost_usd=null`，`cost_status=unknown`。

## 16. 并发保护

## 21. v1.4.5：Planner / Critic 真实接入

默认仍 Mock：

```powershell
scientist-lab plan-next project_rgbt_003 --mock
```

真实必须显式：

```powershell
scientist-lab plan-next project_rgbt_003 --provider real --allow-network
scientist-lab review-plan <plan_id> --provider real --allow-network
scientist-lab tree-plan-next <tree_id> --provider real --allow-network
```

### 21.1 Planner 流程

```text
PlanningContext → Context Sanitizer → Prompt Builder
→ Provider → PlannerOutput Schema → CandidateVerifier
→ Budget → 保存 Plan
```

真实 JSON 仍必须通过 CandidateVerifier、Protocol、TunableParameter、预算、指纹去重。

### 21.2 Critic 双层

```text
LLM Critic + 确定性 Rule Critic
任一规则 blocking → reject
LLM reject → reject 或人工复核
双方 accept → 可 ranking
```

### 21.3 失败回退

默认：真实失败 → **不**静默改用 Mock 冒充真实结果 → 状态 `real_provider_failed` → 用户可显式 replay/mock。

允许显式 `--fallback replay`，且 Plan 必须记录：

