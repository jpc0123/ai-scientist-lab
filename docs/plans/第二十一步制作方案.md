# 第二十一步制作方案：v2.1 真实 LLM 多轮科研闭环

> **本文档为 Scientist Lab v2.1 权威实现方案。**  
> 承接 v2.0 完整 AI Scientist 工作台。  
> 建议基线：`v2.0.0`；开发分支：`feat/v2.1-real-llm-closed-loop`。  
> **核心原则：** 默认 Mock、CI 零网络、真实模型显式启用、禁止静默回退、人工审批不变。

---

## 0. 阶段定位

v2.0 已完成完整工作台与 LLM Provider / 质量治理。当前最大缺口：

```text
系统已经能够调用真实模型
但尚未充分证明真实模型能够根据实验反馈持续调整研究计划
```

v2.1 不增加普通 CRUD / Dashboard / 新 Provider。只解决：

> 真实语言模型能否在受控科研流程中读取当前证据、提出实验、接受审查、获得新结果，并根据新结果改变下一轮规划。

---

## 1. 总体目标

```text
真实实验基线
→ 第一轮 PlanningContext → 真实 Planner → 真实 Critic
→ 确定性规则 → 人工审批 → 真实实验执行
→ Evidence / Claim 回填 → 第二轮 PlanningContext
→ 真实 Planner 再规划 → 验证第二轮使用了第一轮反馈
```

完成后定位：

> 真实模型参与实验反馈迭代的受控 AI Scientist

---

## 2. 不做的内容

```text
真实 LLM 自动生成源码 Diff（→ v2.2）

CUDA + DFINE 正式 Benchmark（→ v2.3）
多用户 / 无人值守连续科研
```

## 3. 验证任务：Digits

CPU、短耗时、无 CUDA、易解释、可多 Seed。初始节点建议 `hidden_units ∈ {64,96,128}`。

## 5. 核心状态机

`RealResearchLoopSession` 主状态：

```text
created
→ baseline_ready
→ round_1_planning → round_1_reviewing → round_1_waiting_approval
→ round_1_executing → round_1_feedback_ready
→ round_2_planning → round_2_reviewing
→ completed
```

失败 / 终态旁路：`provider_failed` / `planner_failed` / `critic_failed` / `candidate_rejected` / `execution_failed` / `feedback_incomplete` / `quality_gate_blocked` / `cancelled`

状态必须持久化；重启不得丢失轮次、调用、审批、执行、Evidence、第二轮上下文。

## 6. 数据模型（摘要）

- `RealResearchLoopSession`：session / project / profile / protocol / status / rounds / baseline & execution nodes / `fallback_allowed=false` / `fallback_used`
- `ResearchLoopRound`：round 级 Planner/Critic/候选/执行/Evidence
- `FeedbackUsageRecord`：证明第二轮使用了第一轮结果（含 `context_sha256`）

详见实现：`src/scientist_lab/research_loop/models.py`

## 31. v2.1 最终定义

> Scientist Lab 能够让一个经过质量评测的真实语言模型，在无静默回退、预算受限、规则验证和人工审批不变的条件下，完成至少两轮「读取实验结果—生成下一实验—执行—接收反馈—重新规划」的科研闭环，并生成可离线复现和审计的完整证据记录。

不代表完全自主科研、无限改实验、自动发论文或绕过人工决策。
