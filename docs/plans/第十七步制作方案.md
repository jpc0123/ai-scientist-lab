```text
实验执行 → 规划与审批 → 有限实验树 → Evidence/Claim
```

## 2. API 原则

1. 统一前缀：`/api/v1`
2. 所有路由调用 `ExperimentService`（及已有子 Service），**禁止**在 API 层复制业务逻辑
3. 统一错误 JSON：`{ "error": { "code", "message", "details?" } }`
4. 列表支持 `limit` / `offset`（及常用过滤：`project_id`、`status`）
5. 危险写操作仍由后端状态机校验；前端二次确认 ≠ 安全边界
6. Legacy `/api/*`（旧控制台）保留兼容，新前端只用 `/api/v1`

### 2.1 核心只读

```text
GET /api/v1/health
GET /api/v1/system/summary
GET /api/v1/projects
GET /api/v1/projects/{project_id}
GET /api/v1/executions
GET /api/v1/executions/{execution_id}
GET /api/v1/executions/{execution_id}/logs
GET /api/v1/trees
GET /api/v1/trees/{tree_id}
GET /api/v1/trees/{tree_id}/nodes
GET /api/v1/trees/{tree_id}/mermaid
GET /api/v1/plans
GET /api/v1/plans/{plan_id}
GET /api/v1/iterations
GET /api/v1/iterations/{iteration_id}
GET /api/v1/evidence
GET /api/v1/claims
GET /api/v1/reports
GET /api/v1/audits
GET /api/v1/patches
GET /api/v1/patches/{patch_id}
```

### 2.2 受控写接口

```text
POST .../plans/{plan_id}/candidates/{candidate_id}/approve|reject
POST .../iterations/{iteration_id}/approve|advance|finalize
POST .../patches/{patch_id}/approve|reject|apply-sandbox|test-sandbox|decide-merge
```

`decide-merge` 仅记录意图，**永不**写主工作区 / commit / push。

---

## 4. 安全边界

- 按钮隐藏 ≠ 授权
- 无任意 Shell / 终端输入框
- 无一键 merge 到主分支
- Patch apply 仅 sandbox；后端重跑 verify / 状态检查
