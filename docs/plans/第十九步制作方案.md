## 1. 明确不做

- 自动 push  
- 自动合并远程 PR  
- 自动发布生产环境  
- 允许 LLM 直接 commit  
- 允许任意 Git 命令  
- 自动解决冲突  
- 自动修改主分支历史  
- `git reset --hard` / `git clean -fdx` / `git push --force` / `git rebase`

---

## 2. 推荐主流程

```text
PatchProposal
→ PatchEvidence 通过
→ merge decision = merge（意图）
→ 创建隔离 Git worktree
→ 应用补丁
→ 检查 git diff
→ 运行受控测试
→ 创建 MergeCandidate
→ 人工批准
→ 创建受控 commit
→ 合并目标分支
→ 再跑回归
→ 成功则完成 / 失败则回滚（revert）
```

任何一步失败，都不能留下半完成状态。

## 5. 核心数据模型

### MergeCandidate

```python
status: Literal[
  "created", "preparing", "testing", "waiting_approval",
  "approved", "committing", "merged", "failed",
  "rolled_back", "rejected", "merge_conflict",
]
```

字段：`merge_candidate_id`, `project_id`, `patch_id`, `patch_evidence_id`,
`source_commit`, `target_branch`, `workspace_path`, `patch_sha256`, `diff_sha256`,
`test_run_id`, `commit_sha`, timestamps。

### MergeApproval / RollbackRecord / ReleaseCandidate

见用户规格；第一版 RC 只本地生成，不自动远程 Release。

---

## 6. Git 安全边界

**允许（固定动作，数组传参，禁止 shell=True）：**

`status` / `diff` / `rev-parse` / `worktree add|list|remove` /
`apply --check` / `apply` / `add <白名单>` / `commit` /
`merge --no-ff` / `revert`

**禁止：** `reset --hard`、`clean -fdx`、`push --force`、`rebase`、
`filter-branch`、任意用户路径 checkout、修改全局 `git config`。

---

## 7. 隔离工作区

```text
<project_root>/.scientist-worktrees/<merge_candidate_id>/
```

- 一个 MergeCandidate 一个 worktree  
- 不复用旧 worktree  
- 不得覆盖主工作区  
- 完成后可清理  

---

## 8. 受控测试 Profile（v1.9.4）

注册表：`syntax` / `unit` / `smoke` / `full_regression` / `acceptance`  
命令只能来自内部注册表，不能由前端 / LLM / PatchProposal 传入。

---

## 9. 受控 Commit（v1.9.6）

系统生成 message，禁止 LLM 自由撰写。Commit 前再次校验：diff 指纹、白名单文件、禁止路径、测试通过。

---

## 10. 冲突与回滚

- 冲突：`merge_conflict`，停止；不自动解决；需重新审批 Patch。  
- 回滚：仅 `git revert`，保留历史；禁止 `reset --hard`。
