> **本文档为 v1.3 权威实现方案。**  
> 承接 `第十二步制作方案.md`（v1.2 科研证据报告与审计 Bundle）。

| 版本 | 解决的问题 |

| **v1.2** | 把实验树整理成可审查、可复现的报告与审计 Bundle |

### 0.1 总体目标

```text
LLMProvider 接口
→ FakeProvider
→ ReplayProvider
→ Provider 配置
→ 严格 JSON Schema
→ 调用记录与成本审计
→ Planner/Critic 对照评测
→ 最后才接真实 Provider
```

### 0.2 严格限制

| 允许 | 禁止（第一阶段） |
|------|------------------|
| Fake / Replay 驱动规划与审查 | 默认直连云模型 |
| 严格 JSON Schema 校验与有限修复 | 自由文本当合同执行 |
| Token / 费用 / 延迟记账 | 无上限无限调用 |
| Mock vs Replay vs Real 对照评测 | 无审计日志上线 |

## 3. v1.3.1 接口草图

```python
class LLMProvider(Protocol):
    def complete(self, request: LLMRequest) -> LLMResponse: ...

class LLMRequest(BaseModel):
    purpose: Literal["planner", "critic", "other"]
    messages: list[dict]
    response_schema: dict | None = None
    temperature: float = 0.0
    max_tokens: int | None = None

class LLMResponse(BaseModel):
    content: str
    parsed_json: dict | None = None
    usage: dict  # prompt/completion/total tokens
    latency_ms: float
    provider: str
    model: str
    request_id: str
```

## 5. 完成标准（整版本）

- [ ] Fake / Replay 可独立跑通 plan-next / review-plan
- [ ] 每次调用有审计记录（tokens / cost / latency）
- [ ] Schema 不合规响应被拒绝或有限修复后仍失败则降级
- [ ] Real Provider 默认关闭，需显式配置与预算
- [ ] 质量评测报告可对比 Mock / Replay / Real
- [ ] 全量回归通过；有限实验树 E2E 仍可运行

真实云调用放到 v1.3.6+，且必须带预算与审计。
