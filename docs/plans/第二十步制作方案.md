# 第二十步制作方案：v2.0 完整 AI Scientist 工作台

> **本文档为 Scientist Lab v2.0 权威制作方案。**  
> Tag 基线：`v1.9.0`；分支：`feat/v2.0-scientist-workbench`。  
> v2.0 的重点不是继续增加底层算法，而是将现有能力整合为一套可安装、可操作、可演示、可审计的完整 AI Scientist 工作台。

---

## 0. 阶段定位

截至 v1.x，Scientist Lab 已完成实验契约、Runner、RGB-T、协议、Evidence/Claim、Planner/Critic、有限实验树、报告/Audit、受限补丁、Web Console、受控合并与 RC。

v2.0 要解决：

```text
用户能否通过一个统一工作台，完成从科研问题、实验规划、审批、执行、证据分析，
一直到报告和版本封存的完整科研工作流。
```

核心定义：

> Scientist Lab v2.0 是一个单用户、本地优先、人工审批驱动、可追溯的 AI Scientist 科研工作台。

---

## 1. 总体目标

```text
创建科研项目 → 选择任务模板 → 注册数据集与运行环境 → 创建实验协议
→ 运行 baseline → 分析结果与证据 → Planner 提出下一步 → Critic 与规则审查
→ 人工审批 → 有限实验树推进 → 生成报告 → 构建 Audit Bundle → 封存项目版本
```

日常以 Web Console 为主；CLI 保留用于调试、自动化、高级操作、验收、故障恢复。

---

## 2. 不做的内容

多租户 SaaS、团队权限、自动付费、公有云托管、无限自主科研、LLM 自动批准实验、LLM 直接 Shell、LLM 直接改主分支、K8s 调度、自动发论文、自动 push 远程仓。

---

## 3. 产品结构（九区）

```text
概览 / 项目 / 数据与环境 / 实验 / 规划与审批
/ 实验树 / 证据 / 报告 / 系统
```

---

## 4. 架构原则

```text
UI 只负责展示和发起操作
API 只负责参数转换和响应
Service 承担业务逻辑
Repository 承担持久化
Runner 承担执行
Verifier 承担安全和科研规则
```

禁止把业务规则写进 React 页面或 API 路由。

## 6. v2.0.1：项目生命周期（当前）

状态机：

```text
draft → configuring → ready → running → reviewing → completed → archived
```

六步新建向导：科研问题 → 任务类型 → 数据集 → 运行环境 → 实验协议 → 确认创建。

任务类型第一版：`general_ml` | `rgbt_detection` | `custom_registered_task`。

交付：模型扩展、Project Service、create/list/show/archive API+CLI、前端列表与向导。

首个验收链：Web 新建 → 六步确认 → `ready` → 重启后仍可 show。
