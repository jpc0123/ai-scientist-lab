## 3. 关键约束

### 3.1 代码上下文

模型只能看到：允许修改的文件、相关接口定义、失败摘要、测试错误、Evidence Gap、Patch 目标、文件内容 SHA256。

### 3.2 严格输出

`PatchProposal` + Unified Diff + 修改理由 + 风险 + 预期测试。禁止 Shell / 整仓替换。

### 3.3 真实 Provider 强制

```json
{
  "requested_provider": "openai-compatible",
  "actual_provider": "openai-compatible",
  "fallback_used": false
}
```

### 3.4 审批防篡改

审批保存 `context_sha256` / `patch_sha256` / `candidate_sha256` / `source_commit`；内容变化则旧审批失效。

## 5. v2.2.1 首个开发任务

```text
CodeContextBundle
→ AllowedSourceFile
→ SourceSnapshot
→ PatchRequest
→ Context SHA256
→ Context Size Budget
```

**第一阶段不调用真实模型。**

验收目标：

```text
给定 Digits 明确失败或小型改进目标
→ 只读取允许文件
→ 排除密钥、环境配置和禁止目录
→ 生成稳定 CodeContextBundle
→ 文件内容与 Git 基线均有 SHA256
→ 重启后可复现同一 context_sha256
```

实现位置：`src/scientist_lab/patching/context_*.py`（复用 `PathPolicy`；Digits 使用 `PathPolicy.for_code_context()`，**不**扩大遗留 PatchProposal 默认白名单）。
