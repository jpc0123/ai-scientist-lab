# 基模后训练：SFT / DPO / RL 数据制作策略

日期：2026-08-25  
范围：只训 **会做下一步研究决策的语言模型**（Planner）。不训检测器。  
配对考题：`[LLM_HOLDOUT_EXAM_CONTRAST_V1.md](./LLM_HOLDOUT_EXAM_CONTRAST_V1.md)`

本文先讲人能读懂的事，再讲怎么切成三类训练样本。`F0` / `F1` 只是旋钮编号，训练时必须同时带上中文含义。

---

## 0. 你到底在训基模做什么

基模已经会写中文、会补代码。它缺的是：**在实验室规则里，看完上一轮实验，决定下一轮试什么。**

所以喂给它的不是「F3」三个字符，而是一场小对话：

```text
你看见：上一轮已经用「可见光+热成像、一开始就拼在一起」跑过了。
        数据、评测、随机种子都不能换。只能换融合做法。
你决定：下一轮改成「两路分开、用门控再融合」，种子保持同一把。
系统执行：真的按这个合同去跑。
```

训练目标：下次再看到类似局面，模型会写出**同样类型的决定**（做对照、不空转、不改考卷），而不是复读编号。

实验分数（低光照小目标准不准）是科学读数，**不告诉模型「你这次决策对不对」**。对错只看：有没有做成公平对照。

## 1. 编号到底是什么（必读）

这些是实验室已经接好的四种 **做法**，不是新发明的网络名字。Planner 只能从这里选，不能自己造第五种。


| 编号     | 人话                 | 实际在干什么                                        |
| ------ | ------------------ | --------------------------------------------- |
| **F0** | 只用可见光，不用热成像        | 关掉热成像，当对照组：热成像到底有没有用                          |
| **F1** | 可见光和热成像一开始就拼成一张图   | 最简单的双模态：两个通道叠在一起再送进检测器。v2.6 的**起点 / 比较基准**就是它 |
| **F3** | 可见光、热成像各走一路，再用门控融合 | 比 F1 更重：两路特征分开提，再决定怎么合                        |
| **N0** | 脖子（特征金字塔）用仓库里的标准版  | 不改融合，只动检测器脖子时的默认档                             |


不要当「发现」选的：


| 编号                     | 为什么不要                                          |
| ---------------------- | ---------------------------------------------- |
| **N1**                 | 另一种脖子（FDPN）。历史上和 F1 拼过，**对 Planner 隐藏**，免得它背答案 |
| **F2 / late_fusion 等** | 目录里没接好，选了等于发明实验，Adapter 跑不了                    |


另外两个常一起出现的词：


| 词         | 人话                                        |
| --------- | ----------------------------------------- |
| **种子 42** | 随机数种子。同一做法换种子 = 问「换一把随机数还稳不稳」，**不是**换融合方法 |
| **低光照切片** | 只在比较暗的图上评小目标。这是考卷，下一轮不能偷偷换成另一批图           |


所以「F1/42 → F3/42」翻译成人话是：

> 上一轮：简单拼接融合，随机种子 42。  
> 下一轮：**只换**成门控双路融合，种子还是 42，图还是同一批暗图。

这才叫对照。若下一轮仍是「简单拼接 + 种子 42」，叫空转。

## 2. 轨迹是什么（读这一条就够）

**轨迹不是一串 F0/F1。**  
轨迹是按时间排好的三拍：**当时看见什么 → 决定做什么 → 后来实际发生了什么。**

下面用仓库里真发生过的 Round 1 写成能读的轨迹。机器编号写在括号里，方便对账，训练时中文和编号要一起留。

### 第 0 轮（比较基准，不是模型发现的）

已经跑完、冻住，当作「上一轮实验」：

- 做法：可见光和热成像一开始就拼在一起（**F1**）
- 随机种子：42
- 数据：RGBT-Tiny，只评偏暗的那些图
- 这句话的意思：以后每一轮都跟 **这一轮** 比，而不是跟「想象中的标准答案」比



### 第 1 轮（一条完整轨迹）

**① 看见（观察 o）**

> 实验室规定：这一轮只能改「怎么融合可见光和热成像」，不能换数据集，不能换评测定义，不能换随机种子。  
> 上一轮已经用「一开始就拼在一起」（F1）、种子 42 跑过了。  
> 还可以选：关掉热成像（F0），或改成两路门控融合（F3）。  
> 不要再提一遍 F1+42，那等于没做新实验。

**② 决定（动作 a）**

> 下一轮改成「两路分开、门控再融合」（F3）。  
> 种子仍用 42，数据和评测与上一轮相同。  
> 原因：这样才能知道「换融合做法」本身有没有差别。若连种子一起换，分不清是方法好还是运气好。

**③ 发生了什么（结果 y）**

> 合同被执行了：Adapter 真的跑了门控融合，种子 42。  
> （后面检测分数涨了或跌了，只写进科学笔记，**不拿来当「这个决定对不对」的标签。**）

把 ①②③ 连起来，就是一条轨迹。  
SFT/DPO/RL 都是从这种「能读完的故事」上切片，不是从光秃秃的 `how_id` 上切片。

反例（P1 空转，也是一条轨迹，但是坏的）：

> 看见：上一轮已经是拼接融合 + 种子 42。  
> 决定：再跑一遍拼接融合 + 种子 42。  
> 发生：GPU 又跑了同一轮实验。  
> 这不是对照。可以当「别这样」的反面教材，不能当 SFT 的正确答案。

## 3. 怎么用轨迹训基模（三类切法）

同一条可读轨迹，切三次：

### 3.1 SFT：教它写出第 ② 拍

把「看见」当输入，「决定」当输出。模型学的是**下一句人话+合同**。

**输入（给基模看的字）：**

```text
【局面】
上一轮实验：可见光和热成像一开始就拼在一起（F1），随机种子 42。
本轮只允许改融合做法，不允许换图、换评测、换种子。
可选做法：
- F0 关掉热成像，只留可见光
- F1 一开始就拼接（已经跑过）
- F3 两路门控融合（还没拿来和上一轮做过对照）

【要求】
请写出下一轮实验：用一句话说明改什么、为什么；并填写合同字段。
```

**输出（教师答案）：**

```text
【决定】
改成两路门控融合，种子保持 42，数据和评测不动。
这样只改变融合做法，才能和上一轮公平比较。

【合同】
做法编号: F3
随机种子: 42
数据集: 仍用 RGBT-Tiny 低光照切片
停止实验: 否
```

编号 `F3` 是给执行器的；**前面那段中文才是基模真正在学的科研行为。**  
没有中文、只留 `how_id=F3` 的样本，模型会背编号，不会做研究。

只收「决定」确实构成对照的轨迹当 SFT 正样本。空转轨迹不要当教师答案。规模：先 200 条跑通，正式 500–2000 条。

### 3.2 DPO：同一局面，一对好/坏决定

还是上面那段「看见」，配两个「决定」：


|             | 人话            | 合同       |
| ----------- | ------------- | -------- |
| 好（chosen）   | 改成两路门控融合，种子不变 | F3，种子 42 |
| 坏（rejected） | 再跑一遍一开始就拼接    | F1，种子 42 |


模型学的是：在**同一段中文局面**下，对照比空转更好。  
不要用「后来检测分数更高」来选 chosen。

坏决定优先用实验室里真发生过的（P1 那种空转）。人因为钱不够、配置不合法而拒绝的，不要当成「想法差」。

### 3.3 RL：同一局面让它说四个决定，用规则打分

把 SFT 的「看见」当题目，让当前模型随便说 4 个下一轮方案。每个方案只按人话规则打分：

- 做法是目录里有的（F0/F1/F3/N0），没有换图 → 加分
- 相对上一轮只改了一件事（只改融合，或只改种子）→ 加分
- 又提一遍上一轮已经做过的组合 → 扣分
- 同时改融合又改种子 → 扣分
- 发明目录里没有的做法 → 扣分

四个决定分数全一样（全对或全错）就丢掉这组。  
**仍然不看检测分数。**

顺序：先 SFT（会写人话决定）→ 再 DPO（压空转）→ 最后 RL。

## 4. 落盘时中文和编号成对出现

每条原始记录至少有两层，禁止只存编号：

```json
{
  "round_id": "v26_r1",
  "story": {
    "saw": "上一轮已经用「可见光+热成像一开始拼接」跑过，种子 42。本轮只能改融合做法。",
    "decided": "改成两路门控融合，种子保持 42。",
    "happened": "合同被执行，跑的就是门控融合、种子 42。"
  },
  "machine": {
    "anchor": { "how_id": "F1", "seeds": [42] },
    "plan": { "how_id": "F3", "seeds": [42], "stop": false },
    "executed": { "how_id": "F3", "seeds": [42] }
  }
}
```

- `story`：给人读、给基模当自然语言输入/输出  
- `machine`：给打标器和 Adapter 执行

缺 `story` 的旧日志：能补写中文再进高可信桶；补不出就降级或丢掉。

对照打标仍然看 `machine`（有没有只改一项），但 **SFT 的 input/output 必须用** `story` **写成完整句子**，合同字段只作为输出里的附录，方便执行。

标签含义用人话说：


| 机器标签            | 人话                        |
| --------------- | ------------------------- |
| `how_contrast`  | 只换了融合做法，其它冻结 → 可当 SFT 正样本 |
| `seed_contrast` | 只换了随机种子 → 可当 SFT 正样本      |
| `idle`          | 和上一轮完全一样 → 只能当反面教材        |
| `fake_contrast` | 嘴上说换了，合同没换                |
| `confound`      | 一次改了两样，分不清原因              |
| `illegal`       | 换了考卷或发明了没接好的做法            |
| `stop_ok`       | 该试的都试过了，决定停止              |
| `unlabeled`     | 故事残缺，丢掉                   |


打标实现：`scientist_lab.llm.contrast_holdout.label_contrast`（看合同；训练文本仍要另写 `story`）。

## 5. 目录、隔离、出门检查

```text
data/llm_posttrain/
  raw/*.json          # 必须含 story + machine
  sft/train.jsonl     # 输入=看见，输出=决定（中文+合同）
  dpo/train.jsonl
  rl/prompts.jsonl    # 只放「看见」那段中文
```

隔离考题（`evals/llm/contrast/` 和旧的 25 道）**永远不进上述目录**。那些是期末卷，用来考「会不会做对照」，不是作业。

一批数据能送去训练前：

1. 每条都能用中文读完「看见 / 决定 / 发生」三拍
2. SFT 正样本都是真对照，不是空转
3. 编号在样本里出现时，旁边有人话释义（本文件第 1 节那张表）
4. 考题原文没有泄漏进训练集

## 6. 和「轨迹报告」里那个词的关系

别处说的 Runtime Trajectory / `how_id` / fingerprint，指的是**同一件事的机器投影**：便于回放、打标、执行。

你要读、要拿去训基模的，是第 2 节那种 **三拍故事**。  
看不懂编号时，先读 `story`；编号只是故事里「选了哪一种已经接好的做法」。

## 7. 实验账本 → 六元组导出 → 训练样本（怎么对应、怎么做）

是的：内核不动，**再映射一层，从导出层出轨迹**。不要把 Plan/GPU 改成按六元组跑。

```text
每轮已有产物（不改）
  Plan / Contract / Run / Result / Review
  + research_events.jsonl
        ↓  只读投影（TrajectoryExporter）
  traces/<run_id>.jsonl     ← 通用六元组，给别人/给训练方
        ↓  再切一刀（本仓库后训练）
  story + 对照标签 → SFT / DPO / RL
```

### 7.1 一轮实验压成几步

建议导出 **4 步**（一步一个六元组）。粒度比「每条 GPU 日志一行」粗，比「整场战役一个文件」细，刚好能训 Planner。

| 步 | 实验室事件 | 人话 |
|----|------------|------|
| 1 | `plan_proposal` | 看见上一轮，写出下一轮计划 |
| 2 | `gate_decision`（可加 `human_governance`） | 系统/人批不批 |
| 3 | `execution` + `metrics_parsed` | 真的跑了，读到分数 |
| 4 | `review_decision`（可加 `memory_write`） | 留下还是丢掉，记下教训 |

`r_t` 这四步都先填 `null`。奖励另文事后生成，不写回账本。

### 7.2 字段怎么填（实验室 → 六元组）

**每步都要带的身份（放进 \(m_t\)）：**  
`project_id` `round_id` `run_id` `event_id` `actor_role` `phase` `plan_id` `fingerprint_id` `git_sha`

**\(h_t\) 一律用 `decision_summary`，不要 CoT：**  
`problem_observed` / `hypothesis` / `selected_action` / `decision_basis` / `expected_effect` / `risk`

逐步对应：

**第 1 步 出计划（`plan_proposal`）**

| 六元组 | 从哪取 |
|--------|--------|
| \(o_t\) | 上一轮已执行合同（how 的人话 + 编号 + 种子）+ 本轮协议：能改什么、不能改数据集 |
| \(h_t\) | 本轮 `decision_summary` |
| \(a_t\) | `{ "tool": "propose_plan", "how_id", "seeds", "stop" }` |
| \(y_t\) | 写出的 Plan 是否合法（schema / 目录内 HOW） |
| \(r_t\) | `null` |
| \(m_t\) | 身份字段 + `reconstructed` |

**第 2 步 批准（`gate_decision` / `human_governance`）**

| 六元组 | 从哪取 |
|--------|--------|
| \(o_t\) | 第 1 步的计划合同（已经发生，可以看） |
| \(h_t\) | Gate 理由或人闸 `reason_type`（仍是结构化短句） |
| \(a_t\) | `{ "action": "approve" \| "reject" }` |
| \(y_t\) | APPROVED / REJECTED；人闸另记 `training_eligible`（默认 false） |
| \(r_t\) | `null` |

**第 3 步 执行（`execution` + `metrics_parsed`）**

| 六元组 | 从哪取 |
|--------|--------|
| \(o_t\) | 已批准的 Contract（HOW、种子、数据切片） |
| \(h_t\) | 可空，或 Adapter 的 how 翻译摘要 |
| \(a_t\) | `{ "tool": "run_experiment", "executed_how_id", "executed_seeds" }` |
| \(y_t\) | `run_state`、主键分数、`metrics_forged`。**分数只在 y，不在 o，也不进对错标签** |
| \(r_t\) | `null` |

**第 4 步 复盘（`review_decision`）**

| 六元组 | 从哪取 |
|--------|--------|
| \(o_t\) | 第 3 步的结果 + 与上一轮的 Δ（这是「已经发生的读数」） |
| \(h_t\) | Reviewer 的 `reasoning_summary` 裁成短结构，或 rubric 字段 |
| \(a_t\) | `{ "action": "KEEP" \| "DISCARD" \| "REPLICATE" \| "STOP" }` |
| \(y_t\) | lesson/strategy id、ClaimGate 状态（KEEP ≠ 声称成立） |
| \(r_t\) | `null` |

其它事件（`materialize`、`fingerprint_check`、`claim_gate`、`memory_write`）可并进邻近步的 \(m_t\) / \(y_t\)，不必每人一行，除非以后要更细的 agent 训练。

### 7.3 从导出轨迹再做训练数据

六元组文件是 **给通用训练方的中间件**。本仓库后训练还要再切：

1. **拼 `story`（人话，强制）**  
   - 看见 = 第 1 步 \(o_t\) 写成第 1 节那种中文  
   - 决定 = 第 1 步 \(a_t\) + \(h_t\) 的人话（「改成两路门控融合，种子不变」）  
   - 发生 = 第 3 步实际执行是否等于决定；第 4 步留下还是丢掉  

2. **打对照标签（只看 machine，不看分数）**  
   比较第 1 步计划 vs 上一轮已执行：只换做法 / 只换种子 / 空转 / 假对照 / 双变量 / 非法。  
   用 `label_contrast`。

3. **进桶**  
   - 对照合格 → SFT：输入=看见，输出=决定（中文+合同）  
   - 同一看见下，合格 vs 空转 → DPO  
   - 看见当 prompt，规则分（合法、单变量、不空转）→ RL；**不要用 \(y_t\) 里的检测分数当 reward**  
   - 空转、假对照 → 失败教材，不当 SFT 正样本  
   - 人因预算拒绝 → 丢掉，不当 DPO 负偏好  

4. **事后奖励（可选，只写导出副本）**  
   `reward_export`：例如对照合格 +1、空转 -2。版本号单独记。换公式不准改 `research_events.jsonl`。

### 7.4 落盘清单

```text
run 目录里已有：
  plan.json  contract  metrics  review  research_events.jsonl

导出（新，只读生成）：
  export/traces/<run_id>.jsonl          # 4 步六元组，r 恒为 null
  export/stories/<run_id>.json          # story + machine + contrast_label
  export/reward_export/<run_id>.json    # 对照规则分，不写回账本
  export/sft/*.jsonl
  export/dpo/*.jsonl
  export/rl/prompts.jsonl
  export/manifests/batch.json           # 源 run、打标器版本、隔离检查
```

命令（不跑 GPU，不改 `research_events.jsonl`）：

```text
scientist-lab export-trajectory --run-dir outputs/v26_r1 --parent-dir outputs/v26_r0
scientist-lab export-trajectory --run-dir outputs/v26_r1 --run-dir outputs/v26_r2 --export-dir export/v26_traces
python -m scientist_lab.llm.trajectory_export --run-dir outputs/v26_r1 --parent-dir outputs/v26_r0
```

SFT 的输入只有第 1 步的「看见」，不要把 4 步六元组拼成一条样本。缺 `research_events.jsonl` 的旧轮次：允许用 Plan/Review **重建** 这 4 步，但必须 `reconstructed=true`，不进高可信 SFT。

隔离考题路径见第 5 节，不得出现在 `export/sft|dpo|rl`。
